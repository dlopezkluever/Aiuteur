# Image generation and editing capabilities for film-frame work (as of 2026-10-18)

Research for GitHub issue #6 ("What can current image models do for consistent frames, composition control, and editing?"), parent map #1.

Scope: facts about what each model's first-party documentation says it supports. This is not a product recommendation. Where a vendor documents nothing, the cell says "not documented" rather than inferring a capability.

Access date for all sources: 2026-10-18. Page dates are given where the page shows one.

## How to read the sources

Each claim cites a source number `[Sn]`, listed with its URL at the end. Each source carries a verification tag:

- **raw**: text grepped from the unrendered page source (curl), so quotes are exact.
- **fetch**: extracted by a WebFetch summarizer. Quoted strings are the summarizer's rendering and should be spot-checked before being relied on in a spec.
- **snippet**: seen only in a search-result excerpt. The page itself could not be read, so treat as unverified.

Several official pages (BytePlus Seedream, Runway's rendered reference, Recraft's appendix, BFL's live pricing table) render client-side and could not be read in full. Those gaps are marked "not retrieved" below rather than filled from third-party sites.

## Key findings

- Google documents "up to 14" reference images total across roles, with per-role caps. Nano Banana Pro has up to 6 object, 5 character, and 3 style references; Nano Banana 2 and 2.1 have up to 10 object and 4 character [S1 raw]. OpenAI's edit endpoint documents up to 16 images, the largest published count in this set [S5 fetch].
- Google's own guide describes fidelity tiers, not just a maximum: Gemini 2.5 Flash Image (Nano Banana) "works best with up to 3 images as input," while Nano Banana Pro "supports 5 images with high fidelity, and up to 14 images in total" [S1 raw].
- Role typing exists only in some APIs. Gemini types references as object, character, or style. Recraft types style references (up to 10). Ideogram's legacy v3 types character and style references. Other APIs take untyped image lists and direct roles through the prompt (for example "Apply the style of image 1") [S1 raw, S22 fetch, S20 fetch, S8 fetch]. No vendor documents a separate "location" reference role.
- OpenAI's edit endpoint accepts up to 16 images, with no documented role parameter. Its only fidelity control is `input_fidelity`, which is not available for `gpt-image-2` [S5 fetch].
- OpenAI's own guide says the model "may occasionally struggle to maintain visual consistency for recurring characters" [S4 raw]. BFL says FLUX.1 Kontext "excels at character consistency, even after multiple edits" [S13 raw]. Character-consistency claims are vendor claims. No primary source gives a benchmark.
- Layout adherence is documented only as region control. FLUX 3 Image uses bounding boxes with "anchor / move / new" kinds and warns that "a new element in a box about 40 x 25 pixels often did not appear" [S10 fetch]. No vendor documents adherence to a whole-frame blocking still used as a composition reference.
- No reviewed vendor documents camera-angle recomposition from a reference image.
- Explicit aspect ratio or pixel size control is present in every reviewed API that documents it: Gemini, OpenAI, Ideogram 4.5, Qwen, Recraft, Runway, FLUX.1 Kontext, and FLUX 3 Image [S1 raw, S5 fetch, S18 raw, S24 raw, S22 fetch, S26 fetch, S13 raw, S9 fetch].
- Masks are supported by some models, not others. Ideogram 4.5 (black marks the edit area), OpenAI gpt-image (transparent alpha marks the edit area, first image only), and BFL FLUX.1 Fill (black preserves, white inpaints) document masks. Gemini, Runway, Qwen, and FLUX.2/FLUX 3/Kontext document none [S18 raw, S19 raw, S4 raw, S14 raw].
- Upscaling is a separate product in some vendors. Recraft documents crisp and creative upscale endpoints ($0.004 and $0.25 per request) [S23 raw]. Ideogram lists upscale endpoints [S21 fetch]. Runway lists a Magnific-based upscaler at 25 credits [S27 fetch]. Gemini, OpenAI, Qwen, and BFL document no image upscale endpoint [S1, S4, S24, S15].
- Published prices are per-image tiers for Gemini and Recraft, per-token for OpenAI, and per-megapixel or credit-based for BFL. Gemini Nano Banana 2.1 is $0.0336 per 1K image standard and $0.0168 batch [S3 fetch]. OpenAI gpt-image-2.5 bills image tokens at $8 input and $30 output per 1M [S6 fetch]. BFL credits are $0.01 each [S12 raw].
- No vendor publishes numeric latency. Google offers thinking levels (minimal, medium, high) and calls Nano Banana 2 Lite "the fastest and cheapest" [S1 fetch, S1 raw].
- Two Google API facts conflict with each other. The pricing page says Nano Banana (`gemini-2.5-flash-image`) "will be shut down on October 2, 2026" (before today) [S3 raw]. The models page lists the same model as "Not deprecated" [S2 fetch]. Verify before relying on it.
- The ticket's own assumptions hold, fail, or depend on the model. Details in the verdicts section below.

## Gaps and caveats

- **Not retrieved from primary sources.** BytePlus Seedream 5.0 reference limits, editing parameters, and prices (the official page is client-rendered and returned only navigation). BFL FLUX.2 numeric prices (dynamic). BFL FLUX 3 Image per-tier prices. Ideogram 4.5 per-quality prices. Recraft appendix sizes. Runway `gen4_image` and `muse_image` exact prompt reference syntax (the `@tag` form appears in a Runway guide excerpt only [snippet]).
- **Conflicting values.** Two summarizer passes over the Gemini guide disagreed on the Nano Banana 2.1 character cap (4 versus 5). The raw page source is authoritative: 2.1 and 3.1 Flash have 4 character images, and Nano Banana Pro has 6 object, 5 character, 3 style [S1 raw]. OpenAI mask size limit: 4 MB [S5 fetch] versus 50 MB [S4 raw]. Qwen input limit: one to three images [S24 raw] versus one to six in a model table [S24 fetch].
- **Deprecation status.** Gemini 2.5 Flash Image shutdown date (October 2, 2026) conflicts between the pricing page [S3 raw] and the models page [S2 fetch]. Imagen 4 is listed as shut down with no date [S2 fetch]. BFL labels FLUX.1 Kontext "previous-generation" and recommends FLUX.2 for editing [S13 raw].
- **Superseded documentation.** The Qwen-Image-Edit URLs now serve qwen-image-2.0 content [S24 raw]. The Ideogram v3 inpaint page is legacy [S20 fetch]. Several third-party sites give different reference limits and prices (for example, a third-party gen4_image schema says 3, consistent with Runway; a third-party BFL price table disagrees with BFL's own pages). These were not used as evidence.
- **Not researched.** xAI Grok Imagine Image 2, Runway `muse_image` capabilities, Z-Image, Qwen-Image-3.0-pro and Wan 2.7 image models (listed in the Alibaba directory), Midjourney, Adobe Firefly, and open-weights variants. Listed here so they are not mistaken for omitted from the search.
- **Multi-view libraries (ticket LOC-014 / LOC-022).** No primary source addresses whether reusing approved frames suffices versus a multi-view library. Out of scope for documentation.
