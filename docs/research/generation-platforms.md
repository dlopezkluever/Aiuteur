# Generation platforms: job model, capabilities, pricing, and usage

Research note for Wayfinder ticket dlopezkluever/Aiuteur#9 (map #1).
Question: how direct vendor APIs (Google Gemini API and Vertex AI, OpenAI, Runway, Kling, Luma, ElevenLabs) and aggregators (fal, Replicate, OpenRouter) expose async jobs, job ids, cancellation, idempotency, machine-readable schemas, pricing and usage, rate limits, versioning and deprecation, data retention and commercial terms, and LLM structured output.

Accessed 2026-10-18. Facts only; no recommendations.

## Method and reliability

- Sources are vendor documentation, vendor SDK source (openai-python on GitHub), and vendor pages surfaced by search. Each claim cites a source ID; full URLs are in the Sources section.
- Page content was retrieved with WebFetch, which returns a model-generated summary of each page, not the raw text. Quoted sentences are as reported by that summary. Re-check exact wording and field names against the live page before using them in code or contracts.
- Several pages were not readable: some returned 404, some returned only site navigation, and some are client-rendered. Those gaps are marked **not verified** in the tables and listed under Gaps. Claims marked **(search snippet)** come from search-result text and were not confirmed on the page.
- Dates: where a page showed a "last updated" date it is given. Otherwise the page is marked undated.
- Several vendors renamed or moved docs during 2026 (Vertex AI is now presented as Gemini Enterprise Agent Platform; OpenAI docs now live on developers.openai.com). Sources below use the current URLs.

## Integration patterns that differ materially

These are observed differences in the documented behavior, not recommendations.

1. **Completion signal.** Webhook-capable: OpenAI (batch, background, fine-tune, and video events), Gemini Batch (`batch.succeeded` / `batch.failed`), Replicate, fal (`fal_webhook`), ElevenLabs (speech-to-text), Kling (`callback_url`, per snippets). Poll-only in the reviewed docs: Luma Agents, Gemini Veo operations, Runway (SDK wait helper and `GET /v1/tasks/{id}`), OpenRouter (no async job model at all). The same vendor can mix both: Gemini batch has webhooks while Veo operations are polled.
2. **Webhook authentication and delivery.** OpenAI: Standard Webhooks signature headers; up to 72 h of retries; duplicates possible [S16]. Replicate: HMAC-SHA256 over id, timestamp, and body; `webhook-id` stable across retries [S45]. fal: no signature described on the page; retries are possible and `request_id` is the suggested dedupe key [S41]. ElevenLabs: signature scheme not confirmed on reviewed page [S36].
3. **Status vocabulary.** Terminal success is named differently across providers: `JOB_STATE_SUCCEEDED` (Gemini batch) [S1], `completed` (OpenAI batch, OpenAI background, Luma) [S15][S17][S33], `succeeded` (Replicate, Runway) [S44][S28], `SUCCEEDED` (Runway task) [S28], `COMPLETED` (fal) [S41], `OK` (fal webhook) [S41], and `succeed` vs `succeeded` across Kling doc versions (search snippets) [S31]. Replicate's create page sample uses `successful` while its lifecycle page defines `succeeded` [S44][S49].
4. **Creation is not idempotent in some APIs.** Gemini batch creation makes a new job on each identical call [S1]. The OpenAI SDK generates per-request keys but does not send them by default [S24][S25]. fal retries automatically unless `X-Fal-No-Retry` is set [S41]. Where no mechanism is documented (Replicate, Runway, Kling, Luma, ElevenLabs, OpenRouter), the observable behavior on a retried create call is not stated in the reviewed docs.
5. **Cancellation semantics differ by queue state.** fal: queued work is removed; in-progress work may still finish [S41]. OpenAI batch: cancelling for up to 10 min with completed work billed [S15]. OpenAI background: cancel is idempotent [S17]. Replicate: canceled runs are billed for run time; aborted runs are not [S48][S49]. Luma: no cancel [S33]. OpenAI Videos: no cancel, delete only [S22]. Runway: aborting the SDK wait does not cancel the task [S28].
6. **Output retention windows are short for some.** Replicate API outputs: 1 h by default [S47]. Luma output URLs: 1 h presigned [S33]. OpenAI Videos download URLs: 1 h [S22]. OpenAI background response temporary store: about 10 min [S17][S19]. Gemini Veo files: 2 days [S7]. Gemini batch results: 6 weeks [S1]. OpenAI batch output: 30 days after completion [S15]. Persisting results is the caller's responsibility on the short-window providers [S22][S47].
7. **Download authentication differs.** Gemini Veo: file fetched with the API key via the video URI [S7]. OpenAI Videos: `GET /videos/{id}/content` [S22]. Luma and fal: presigned or media URLs with expiry [S33][S41]. Replicate: output file URLs (retention above) [S47].
8. **Billing units vary by modality.** Tokens (Gemini, OpenAI, OpenRouter, Replicate LLMs), seconds (Veo, Runway, fal video, Replicate hardware time), images or megapixels (Gemini image, Luma Agents, fal), characters (ElevenLabs TTS, OpenAI TTS), credits (Runway, OpenRouter), and per-song (Lyria) [S3][S23][S27][S37][S42][S48][S51].
9. **Usage reporting timing.** OpenRouter returns cost in every non-streaming response and by id afterwards [S51]. Runway returns realized cost in credits in Model Router responses [S27]. fal exposes a pre-run price lookup and usage line items [S42]. ElevenLabs points to dashboard analytics [S37]. For Gemini and OpenAI, per-response usage metadata was not verified in this session.
10. **Rate-limit signaling.** OpenAI: `slow_down` 429 can fire within nominal limits and asks for gradual ramp [S18]. Gemini: spend-based windows and 429 `RESOURCE_EXHAUSTED` [S2]. Luma: concurrency rejections use a fixed `Retry-After: 60` with no `X-RateLimit-*` headers [S33]. OpenRouter: 429 headers only on platform limits; mid-stream errors arrive as SSE events, not HTTP status [S53]. ElevenLabs: over-limit requests queue rather than fail, per plan concurrency (search snippet) [S38].
11. **Model identifiers and retirement.** Gemini: preview and stable IDs with published shutdown dates [S5]. OpenAI: dated snapshots with `shutdown_date` in the model endpoints [S20]. Replicate: versions are the unit of change [S50]. OpenRouter: provider-set `deprecation_date`; retired model returns 404 (search snippet) [S56][S57]. Vertex: deprecation covered by Terms of Service; no date rule on page [S9].
12. **Zero data retention is configured per request or per account.** OpenRouter: per-request `provider.zdr`, account, or guardrail [S55]. OpenAI: ZDR requires approval and excludes batches and files [S19]. Gemini: ZDR via settings (Interactions API `store=false`, caching off, no Live API session resumption) [S8]. ElevenLabs: `enable_logging=false`, enterprise only [S36].
13. **Same model, different terms by surface.** Gemini API free tier uses inputs for product improvement; Gemini paid tier and Vertex/Agent Platform do not train on customer data by default [S4][S8]. This is a surface-level difference, not a model-level one.
14. **Quota scope.** Gemini API: per project, spend tiers, 10-min spend windows [S2]. Vertex/Agent Platform: per project and region, with Dynamic Shared Quota for newer models [S11][S12]. OpenAI: per organization and project, with tiers by credit purchase [S18]. OpenRouter: global capacity; additional keys do not raise limits [S53].
15. **Batch discounts.** Gemini batch and OpenAI batch both list about 50% of synchronous price [S1][S15][S23]. Replicate and fal do not describe a batch discount on reviewed pages.

## Gaps and unverified claims

- **Vertex AI / Agent Platform:** batch job body (states, cancel semantics, notifications), quota numbers per model, 429 retry details beyond the summary, pricing, deprecation table, and data-governance details beyond the summary were not fully readable. Reference and deprecation pages returned 404 or navigation only. Vertex batch cancellation and job retention are not verified.
- **Gemini API:** `generateContent` idempotency not verified; per-response usage metadata not verified; Veo pricing unit given only as "per second" on the pricing page.
- **OpenAI:** per-response usage object not verified; full structured-output schema subset not read (page truncated); batch webhook payload schema not read; Videos API is shut down, so its retention and pricing are historical.
