## Compiler, Package and Rendered request

- Resolve: `story.resolveSourceMaterial(ReadTx, Scope, project, object)` reads the head through `history.read` and returns the text plus `(unit "content", object, sequence, fingerprint)` read from the frozen Revision fingerprints. `workflows.previewTreatment` assembles `ResolvedInputs` (Resolve lives in the owner, MODULE §2.1).
- Compose: `scaffold:operation` (provenance `scaffold`, versioned wording in `compiler/src/scaffold.ts`, with an `evidence` field) and `source-material` (provenance `verbatim`, its source unit and captured input). `binding`, `base`, `instruction` and `writing-style` are absent. References and Package parameters are empty for text.
- Layer catalog tiers: `writing-style` Tier 1 (decision 3); every other text layer Tier 0, read from Package §7.2 by analogy (Facts bind; creator instruction ≈ `guidance`; §14: "context that does not fit is not truncated"). Only `scaffold:operation` and `source-material` are composed in #101.
- Fit: counts the wrapped layers with the profile's counter against `max − margin`; omits whole layers lowest tier first and, within a tier, from the end of the canonical order, with outcome `omitted-optional` and reason `over-limit`; Tier 0 is never omitted. Tier 0 over the room is `blocked` (`over-limit`, needed, limit, unit, exits `another-model` and `edit-layer` per Tier 0 layer; no "send anyway"). An `unknown` prompt limit is read conservatively as `blocked` (`limit-unknown`, exit `another-model`). `maxOutputTokens` is sent at the profile maximum (`param-honored`, `model-maximum`) or reported `param-unsupported`. Rewrites: controllable ones turned off by their parameter, `always` recorded, `unknown` recorded as `undeclared-provider-rewrite` (PROVIDERS §4.3: assumed `always`).
- Render: dialect `neutral-text@1`, data plus one pure function in `providers`. Each carried layer becomes one text part `[[key]]\n<layer text>\n[[/key]]\n` with its `layerKey` and `layerDigest` (sha256 of the layer text). Parts are concatenated with nothing between. `digest` is sha256 of canonical JSON of the Rendered request.
- Purity: `compiler` imports only `contract` and the `providers` Catalogue face (its package dependencies say the same); no Store, clock, randomness, environment or transport.

## Catalogue, profile and price

- Profile sections (PROVIDERS §4.1): identity and lifecycle (`offeringId`, `modelId`, `family`, `adapterId`, `dialect`, `kind`, `tier`, `stability`, `shutdownOn`, `successorModelId`), operations (`operationClasses`, `operations`), input modes with the §4.2 predicate form (shape only), reference constraints, reference binding, duration, extension, output, audio, text (§13), controls, limits (`prompt`: unit, counter, max, margin; `output`; `requestBytes`; `policyNotes`), cost (rule only; no price in a profile, §14), run behaviour, known limitations. Evidence per field via `declared(value)`/`declared-none`/`unknown`.
- Status is the Catalogue's operational overlay per Offering, not snapshot content (§10.1, §10.3): a status change keeps the snapshot id.
- F10 at load, after the schema: dialect known; classes unique and of the profile's family (`world.generate` excepted); duration default inside its set, or inside its range and on its step; duration set unique; extension needs a declared duration; prompt margin below the limit; token rule only on text, same counter as the prompt limit, needs a declared maximum output and `outputMin ≤ max`; duration billing rules need a declared duration; a cloning Offering must declare `delete voice` and a known authorisation precondition (VOICE §2.4, §5.3). Catalogue level: Offering ids unique, ranked Models exist for the class, price entries name a known Offering, a class it performs and a unit its rule bills, with no duplicates. A `Catalogue` value is obtainable only from `loadCatalogue`.
- Selection (Automatic, as far as T0a needs): Offerings of the class, `active` only, not `unknown` on an identity-critical field (prompt limit and counter, billed-quantity rule, duration, output); ordered by the curated rank, then Model id, then Offering id. Result: Model, Offering, snapshot id, `source: automatic`, reasons (`default-by-policy`, `skipped:<model>:<reason>`), or `unavailable` with the reasons. No overrides, credentials, needs filter, circuit breaker or substitution.
- Synthetic Catalogue (`testing/fake-catalogue.ts`): `fake-text` (selected), `fake-text-undocumented` (unknown prompt limit), `fake-text-preview` (preview status), and the existing video and image fakes. All values are `assumed` and synthetic, including the prices.
- `spend.estimate`: from the Rendered request, the profile's rule and the Offering's price entries. Point (request determines cost), Range (token text, or a price past its review age widened by the drift allowance), Unknown (`no-billed-quantity-rule`, `quantity-undetermined`, `no-price-entry`, `stale-price-entry`). Money is integer micro-units of USD; minimum rounds down, maximum up. Basis records the request digest, quantities and entries.
- `generation.preview`: one `compile` call; the estimate prices that call's Rendered request and names its digest. It takes no Store, transaction or transport.
