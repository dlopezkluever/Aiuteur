## Assertions

- The test reads the read model through the browser's own session (`inputReadSchema`) and compares it with the displayed text, revision and role; the Store row is read directly with SQL. Expected values are not taken from the DOM or a test-only source.
- Reload: the read model before and after is equal; the screen shows the same text and revision.
- Stale client: tab 2 changes the role (revision 2). Tab 1, still at revision 1, writes with base 1. The server answers `StaleBase` (existing history gate, unchanged); no Revision is added; one `stale-base` Attempt is kept; tab 1 re-renders revision 2, the server's role, the notice and the kept-aside line.

## Decisions taken

1. **Client framework React 19 with Vite; browser driver Playwright (Chromium).** Reason: smallest widely supported pair that gives a built static client (the spec requires "the built `web`") and a real browser with a documented tracing path (VERIFICATION §4 names Playwright as the candidate class). Not a design system: one stylesheet, no routing library, no state library.
2. **No new HTTP framework for static serving beyond `@hono/node-server`**; `web` is the process role that serves both.
3. **`GET /api/session` is new** because a reload holds only a cookie, and the client must not store the Account id.
4. **`apps/` joins the workspace** (`apps/web`); `esbuild` build scripts are denied in `allowBuilds` (Vite's own bundled binary is not needed at install).
5. The E1 test builds the client itself into a temp directory so it never reads a stale build and leaves no `dist` in the tree.
6. Sign-in uses Better Auth's own route as forwarded (no contract-owned body), as FC2 already says.
