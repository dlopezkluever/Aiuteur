## What the pipeline is

One workflow, `.github/workflows/pipeline.yml`, one job named `verify`, on every push and every pull request to `main`. It runs `pnpm static` then `pnpm required`; `pnpm pipeline` is both, so the same command runs locally.

| Script | Runs | Gate |
|---|---|---|
| `pnpm typecheck` | `tsc --noEmit` | VC1 types |
| `pnpm rules` | `vitest run tools/arch-rules`: R19, R20, EI12 (existing) and **R9, R24, `console` ban (new)** | VC1 lint, architecture rules, vendor-name search, console ban, R24 |
| `pnpm secrets` | `tools/verify`: secret shapes over tracked files | VC1 secret scan |
| `pnpm audit:deps` | `pnpm audit --audit-level=high` | VC1 dependency audit |
| `pnpm generated` | migrate an empty database, then `schema.ts --check` and `vocabulary.ts --check` | VC1 generated-code equality (D1, D3 inputs) |
| `pnpm required` | `vitest run` with a JSON report, then `tools/verify/scripts/require-ran.ts` | Everything else, below |

`pnpm required` runs every suite: VC2 (compiler goldens, version-bump judge), VC3 (properties), VC6 (generated mock server, neutral unknown vocabulary), VC10 lines 1 to 5, 7, 8 (and the record half of line 6), Store, Scheduler and `ProviderTransport` conformance (VC4), VC5 harness, VC7 G1 to G11 as they exist, VC8 D1 to D9 as they exist (`t0-01` D1 to D4, G-gates; `t0-03` D5, D6; Store conformance D9; the P11 purity seam).

**PostgreSQL.** The job has a `postgres:15` service container with trust auth (the runtime roles have no passwords, as in the existing suites' disposable cluster). `TEST_POSTGRES_URL` and `MIGRATION_DATABASE_URL` are set at job level. The suites already throw when `TEST_POSTGRES_URL` is unset, so missing PostgreSQL fails; it never skips. ffmpeg is installed because the fake-media suites run it and fail when it is absent.

**Fail closed.**
- Steps use `bash -e`; no `continue-on-error`, no matrix, no optional job. One job means one required check name, `verify`.
- `require-ran.ts` reads the Vitest JSON report and fails on: no tests, any failure, any skipped/pending test, any todo, or a **required suite file that ran no passing test** (11 named suites in `tools/verify/src/skips.ts`, covering Store, Scheduler, `ProviderTransport`, VC2, VC3, VC5, VC6, VC10, the R-rules). A missing report fails the script.
- `pnpm required` exits non-zero if Vitest or the check does.

## Decisions taken

1. **No new lint tool.** The repository has no linter; its lint is the AST rules in `tools/arch-rules`. R9 (vendor-name search over code, JSON and SQL under `packages`, `apps`, `tools`; adapters, `packages/providers/catalogue/` and the rules' own sources are the homes), R24 (reads of `process.env`, `import.meta.env` and `NODE_ENV`, `VITEST`, `CI` outside composition roots, scripts and tests) and the `console` ban were added there, as `Violation` rules with fixtures. `FIXTURES`-style tests live in `static-rules.test.ts`. One finding per rule and line.
2. **Secret scan is a small in-repo scanner** (`tools/verify`), not an external tool: recognisable credential shapes over `git ls-files`, a value labelled `synthetic` is exempt from the generic assignment shape only, and lockfile/snapshot/binary files are skipped. The scanner reports shape and location, never the value.
3. **Dependency audit found a real failure at the base.** `nodemailer@7` carried 4 high advisories (`packages/mail`). The gate would have been red on arrival, so `packages/mail` moves to `nodemailer ~10.0.6` (resolved 10.0.16) with `@types/nodemailer ^8`. `createTransport` (the only call) is unchanged and `mail`'s tests pass. The newest release (10.3.1) was not used; `~10.0.6` is the line that clears the advisories. No `minimumReleaseAge` policy was established by the effective configuration, so none is claimed. Three moderate advisories remain below the `high` threshold; threshold raised only if the creator wants it lower.
4. **VC6 and VC10 had no code to gate; the minimum was added.**
   - `contract/responses.ts`: `ROUTE_RESPONSES`, the success body schema and status of every non-auth route, typed so a route added to `ROUTES` without an entry does not compile (FC2, additive).
   - `contract/vocabulary.ts`: `readVocabulary`, a closed vocabulary read that returns a neutral `Unknown` for an unlisted value.
   - `testing/mock-server.ts`: `createMockServer`, generated from `ROUTE_RESPONSES` through JSON Schema. VC6 asserts each route's mock body parses with its own schema; "server against the same schema" is every `api` suite, which parses answers with the same schemas.
   - `providers/catalogue.ts`: `bootCatalogue(environment, data)` (VC10 line 4: a production boot with any fake Offering is refused) and `readiness(environment, catalogue)` (line 8: a production process reporting a fake is not ready).
   - `store/derived.ts`: `fakeGenerationCount`, the nightly derived check of line 8, content-free, tested on a real database.
   Lines 1 (type), 2 (R19), 3 (R24), 5 (gate), 6 (record), 7 (bytes) were already implemented and tested, or are covered by the rules above. No Draft product contract changed meaning.
5. **Line 6 split.** The record half (the Generation's `testProvider` flag, read through the trace) is tested. The user-visible mark on a Frame, Take or inspector header is VC10 line 6's UI half and joins in T0-09; no browser or UI was added.
6. **Branch protection is not changed here.** Requiring the check `verify` on `main` is repository settings (shared state); the owner needs to set it (see follow-ups).
