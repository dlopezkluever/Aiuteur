## Decisions taken (from repository authority; no creator input was needed)

1. **The text fast path claims its own Job** (RUNTIME §4.6): `execute` creates the Generation and Job in one transaction, then calls `jobs.claim(1, jobId)` through the Scheduler port and runs the single dispatch path in the request. No worker loop exists yet; a Job the fast path cannot claim stays durable and due.
2. **Idempotency is keyed by the Initiation's action id** (the request's `idempotency-key`, JOB-LIFECYCLE §4). A replay returns the Generation that already exists and sends nothing. A blocked fit or an unavailable selection is not stored, so a retry after the cause changes can create.
3. **Transaction boundaries** (JOB-LIFECYCLE §3, §11): (a) create: idempotency row, Generation with every trace field, capture edges through `history`, Job, `job.state_changed` event; (b) write-ahead intent: `queued → submitting`, before any provider call; (c) settle: call log, G1 validate, `history.commit` of the Option (actor `generation`, cause `ai_generation`), run history, settlement with the actual cost, the Job's terminal state and the `generation.settled` event. A rejected or failed result settles the same way without an Option.
4. **The F3 gate is one pure function over the closed, ordered `DISPATCH_GATE_CLAUSES`**: status, snapshot, credential, fit, inspector-digest, estimate, environment, authorised. `authorised` holds its reserved last position and refuses only voice work (`audio.transform`, `audio.speech`, `audio.voice`), which nothing can authorise before EI7. No spend admission (`spend.admit` is T0-06's). The estimate clause refuses only an unconfirmed Unknown estimate, and nothing confirms in T0-05.
5. **The #101 billed-quantity seam mattered and was resolved minimally**: `billedQuantity` on the adapter face returns `readonly BilledQuantity[]`, and `succeeded.reportedCost` is an array, so token text bills input and output separately. Media rules return one entry. `spend.actual(reported, entries, billed)` prices what the provider reported.
6. **Synchronous text** gets one new `SubmitResult` variant, `completed` (status inline). The fake text profile declares its run behaviour (idempotency `neither`, no webhook, maxRuntime 120 s, no cancellation, output retention `declared-none`, an error map). This gives the profile a new snapshot id; the VC2 golden judged it `stale` (fixture change, replay unchanged). It was regenerated with `--update`: Rendered request and digest unchanged (`sha256:9b573f…`), and the new id is appended to the golden's history.
7. **Choose is a Decision** (`type: choose`) through `history.decide`, creator only, refused for another project or kind, and gated by a lock like a commit. "Chosen" is derived: the project's latest choose Decision on a Treatment Option names it. Nothing is stored as a flag (D6).
8. **The Treatment Option kind is a block document**. A T0a Option holds paragraph blocks only, and its first Revision is all `ai_generated` runs naming the Generation. The `dialogue` block kind (speaker attribute, delivery and line fields) is in the shared block schema (EI4) but not admitted into a Treatment Option.
9. **Scheduler access** (RUNTIME §5): four SECURITY DEFINER functions `job_claim`, `job_extend`, `job_release` and `job_wake`, executable by the `scheduler` role only. They run as owner and see every Account's Job rows only while a transaction-local `aiuteur.claim` flag is set, through a second policy `scheduler_claim TO owner`. They return ids, states and lease tokens, never content. The `scheduler` role has no table privilege (D4 unchanged for it).

## Raised (open questions, non-blocking)

- REJECTED and gate-refused Generations record `failureClass` `unknown` (rejected) or the clause's class (refused). JOB-LIFECYCLE names no failure class for a guard rejection; T0-06 may want its own.
- The Postgres `job_claim` takes a transaction-scoped advisory lock, so claims serialise. That is correct for one process; the claim-throughput shape for many workers is a later RUNTIME concern.
- `integer` rather than `bigint` for the event sequence and counter, because `schema.ts` has no bigint mapping. That is ample for T0; revisit with the outbox consumer.
- `compiler/test/golden.ts` keeps its own copy of the GP-S source paragraph. Pointing it at `GP_S_SOURCE_TEXT` would change a judge file, which SWARM §7 reserves for a verifier-reviewed change.
- Follow-ups from #100 and #101 remain (idempotency-key charset at the database, the concurrency-overlap test); not folded in.
