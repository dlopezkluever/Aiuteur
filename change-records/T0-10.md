## Decisions taken

1. No tracker SDK; the adapter posts the envelope. No message in events (it is free text that can carry a prompt).
2. Fail-closed redaction over cosmetics: a short registered secret may mangle a value; it never leaks.
3. The web's text fast path runs the fake-provider Job, as RUNTIME §4.6 says; the worker claims no Job yet (no executor it owns exists). It proves the database, stamps the tick and pings the heartbeat.
4. Worker liveness lives in the database, read through the `scheduler` identity, so web and worker cannot disagree about time and no new monitoring system exists.
5. Rollback is restricted to digests that ran on this host; this is the whole "release history" (a list of digests).
6. `current: unknown` blocks deploys. A deploy cannot be trusted to start from a belief the system does not hold.
7. The staging smoke Account is created by a script run once, before the first deploy; the Account's login is read by the smoke alone.
8. Postgres keeps the migration-1 role model; only passwords were added.
