## Decisions

1. **Repository layout: one pnpm workspace.**
   - What: a TypeScript monorepo with one package per module under `packages/<module>` (`@aiuteur/<module>`) and repository tooling under `tools/<tool>`. Each package's `exports` names only `./src/index.ts`, so a **bare** specifier (`@aiuteur/providers/src/profile.ts`) cannot reach its internals. Source is consumed directly: Bundler resolution, `.ts` import specifiers, no build step yet.
   - **Correction (repair).** `ef22362` said this enforces R12. It does not: a relative path into another package (`../../providers/src/profile.ts`) compiles and runs, as the verifier showed. **This commit does not enforce R12.** #97 assigns R19 and R20 only; R12 is one of the "R1–R24 static rules" that T0-07 makes a VC1 gate. See Raised item 10.
   - Why: #97 owns the layout. One graph with per-module entries matches MODULE §0. Packaging for deployment stays with the tickets that deploy.
2. **Test runner with property testing: Vitest 5 with fast-check 4.**
   - What: TypeScript runs natively, and fast-check is used for P1 over arbitrary Rendered requests.
   - Why: #80 C2 item 11 assigns this to T0 at first need. The R20 lint bans Vitest's module-mocking APIs.
3. **TypeScript 7 (`tsc --noEmit`), strict, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `erasableSyntaxOnly`.**
   - What: Node ≥ 24 runs `.ts` scripts by type stripping.
   - Why: TypeScript was already settled. The flags make illegal states harder to write.
4. **R19/R20 checker: `tools/arch-rules`, judged on bindings and resolved imports.**
   - Engine: `oxc-parser` for the AST and `oxc-resolver` for resolution, about 180 lines. TypeScript 7 has no JavaScript compiler API, so the checker uses no type checker. This is not a pre-selection of the VC1 lint tool, which T0-07 chooses.
   - Scope: every `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.mjs` and `.cjs` file except `node_modules`, the top-level dot-directories (git, agent and tool configuration) and the top-level `docs/`, `_inputs/` and `prototypes/`. Nested dot-directories are scanned, which closes a hole in `ef22362`.
   - R19 imports: every static import, re-export and literal `import()` is resolved with one resolver configured like the repository: Node's `node`/`import` conditions, package `imports` and `exports`, workspace symlinks to real paths, and the root tsconfig's `paths`. A file that is not test-side (`testing/`, a test file, a local, ci or staging composition root) fails when the target is in `testing/`.
   - R19 classes: an `extends` whose base is bound, under any local name or a namespace import, to `FakeTransport` from a module resolving into `testing/` fails outside `testing/`. An `implements` bound the same way to `ProviderTransport`, `RealAdapter` or `FakeAdapter` from `providers` fails outside the adapters and `testing/`.
   - R20: a member access fails when it selects `mock`, `doMock`, `unmock`, `doUnmock`, `importMock`, `importActual` or `spyOn`, by name or by a literal key, on `vi` or `vitest`. The object counts under any local import alias, as a member of a namespace import of `vitest`, or as an unimported global. Destructuring those names from it also fails. `jest.*` mocking and node:test's `mock.module` are matched by name, as in `ef22362`.
5. **What R19 counts as a test or a composition root.**
   - What: a test is `*.test.ts` or a file under a package's `test/`. A non-production composition root is `**/composition/{local,ci,staging}.ts`.
   - Why: no composition root exists yet. The ticket that adds the first one may move the convention, in the same change.
6. **R19 also refuses a `ProviderTransport` implemented outside `packages/providers/src/adapters/` or `testing/`, and an `extends FakeTransport` outside `testing/`.** VERIFICATION §3.2 line 2 asks for both.
7. **(Unchanged by the repair.) R20 bans `spyOn` as well as `mock`, `doMock`, `importMock`, `importActual`, `jest.mock`-family calls and `mock.module`.** R20's purpose is that "no test can stub an owning module's function" (VERIFICATION §4), and `spyOn` on a module namespace does exactly that. `vi.fn()` stays allowed.
8. **The fake's output files.**
   - Image: rendered in TypeScript per output.
     - Content: a white band with "TEST PROVIDER" in black over yellow and white hazard stripes.
     - Format: 640×360 PNG.
     - Tags: `tEXt` `Aiuteur-Test-Provider=TEST PROVIDER`, plus the operation reference.
   - Video: the committed `packages/testing/assets/test-provider.mp4` (67 KB, 2 s), built from the same raster.
     - Codecs: H.264 video with a 1 kHz AAC tone.
     - Tags: `title` and `comment`.
     - Reproducibility: `scripts/generate-video-asset.ts` with ffmpeg in bit-exact mode gave the same bytes on two runs.
   - Why: the video plays in a browser for later E1 work, and committing the asset means the fake needs no ffmpeg at runtime.
9. **The tests need ffmpeg and ffprobe on `PATH`.** The mark oracle decodes with an independent decoder and fails rather than skips when ffmpeg is missing. T0-07's pipeline must provide them.
10. **Fake profiles.**
    - What: `FAKE_VIDEO_PROFILE` and `FAKE_IMAGE_PROFILE` together cover webhook verifiable and none, cancel best-effort and none, and idempotency by key and by lookup. A test asserts that coverage.
    - Evidence: run behaviour cites platform research #9 as recorded in JOB-LIFECYCLE §9. Synthetic values (error codes, billed rules) are marked `assumed`.
    - Constraint: the fake requires its run behaviour, and its billed-quantity rule, to be `declared`.
11. **Scripted behaviours form a closed, content-free list.**
    - The list: `fail-at-submit`, `fail-while-running`, `lose-submit-response`, `duplicate-callbacks`, `reorder-callbacks`, `complete-despite-cancel`, `run-for`.
    - Each must name the run-behaviour field it exercises, and the snapshot must declare a value that permits it.
    - Scripting an undocumented error code is allowed: it cites the declared `errorMapping` and exercises that map's *Unknown, maybe billed* fallback.
12. **The profile snapshot id is `sha256:` of canonical JSON** (sorted keys) of the profile content.
13. **`ManualClock` / `FakeClock` is a minimal injected virtual clock for the fake.** The Clock+Ids port (FC5) and its virtual time arrive with verification step 2, which may replace it.
14. **Suite shape.**
    - What: a fake subject runs every case; a real adapter's probe subject runs only P1 wire parity, because `wire-capture` is a test hook with no network.
    - Supplied requests carry a hand-derived billed quantity, so "honest billed quantity" is checked against the provider's documented rule rather than against the adapter's own arithmetic.
15. **This record lives at `change-records/T0-00.md`, kept with the change.** The record format is spec-level (SWARM §12).

## Raised

1. **Status vocabulary (FC10).** PROVIDERS §7.2 lists the neutral `observe` statuses as `pending`, `running`, `succeeded`, `failed` and `unknown`. JOB-LIFECYCLE §6.1 also expects a provider answer of "cancelled", and §6 needs a reliable cancel to be confirmed. The Draft adds `cancelled(billing)`. Docs steward: align PROVIDERS §7.2.
2. **Placeholder owners.** `RenderedRequest` is FC8 (`compiler`) and `CredentialHandle` is FC5 (the credential seam). Both sit in `providers` as Draft placeholders and move to their owners, with every caller migrated, when those contracts land.
3. **Digest check (Package P1).** P1 says the adapter "accepts only a Rendered request identified by its stored digest". `SubmitInput` carries the digest, but no transport checks it yet, because the digest algorithm belongs to FC8. Revisit when `compiler` lands.
4. **Deferral (FC10).** JOB-LIFECYCLE §3 has submitting → queued when the provider refuses *before accepting* (429, 503). PROVIDERS §7.2's `submit` outputs have no distinct deferral result, and this Draft adds none, because no #97 case needs it. The Job lifecycle tickets should settle it, as an additive `submit` outcome or a declared class.
5. **The synchronous shape (PROVIDERS §7.5)** is deferred to the first synchronous adapter (the T0a LLM): `submit` returning a terminal status.
6. **R22.** The trace fields propagated to the provider are not in `SubmitInput`. That is verification step 5. #97 narrows R22 to "a returned operation reference".
7. **Probe subset.** It holds only P1. VC13's live smoke ("billed quantity within tolerance", "one known-bad request maps to its class") is built with the first real adapter.
8. **Glossary.** The case title says "P1 wire parity", the term VERIFICATION §3.3 and #97 use. The glossary's *Avoid: parity test* concerns naming a conformance suite, so the title was kept.
9. **Not verified here:** any pipeline run (none exists until T0-07); a real adapter in probe mode (none exists).
10. **R12 is unenforced until its gate lands.** BUILD §1.3 says R1–R24 are enforced "from the first commit". #97 assigns only R19 and R20, and T0-07 makes the R1–R24 static rules a VC1 gate. Until then, a relative import into another package's private file is not refused. The repaired checker already resolves every import to a file, so T0-07 could build R12 on it. I did not pull that work into #97.
11. **What R19 and R20 deliberately do not check** (Decision 16).
    - R19 enforces *declared* implementation ownership (`implements`) and fake identity (`extends FakeTransport`). It does not prove that no object elsewhere is structurally assignable to `ProviderTransport`. VERIFICATION §3.2 line 2 says "a `ProviderTransport` implementation outside the adapters or `testing/` fails the build", and the line 1 brand already stops a fake reaching the production root. A structural transport written outside the adapters without `implements` is left to review, or to a type-aware VC1 rule if T0-07 wants one.
    - A base class re-bound through a local variable (`const Base = FakeTransport`), a mocking function obtained through `Reflect.get`, `.call` or a non-literal key, and non-literal or unresolvable module specifiers are not judged. These are not demonstrated failures, and the checks target mistakes and straightforward evasions.
    - Vitest configuration (`alias`, `plugins`, `setupFiles`, `globals`) is not restricted. R20 bans module-mocking APIs, not configuration features, and no owning document bans them.
    - The test-file and composition-root conventions (Decision 5) are path-based. A production entry point named `composition/ci.ts` would be allowed to import `testing/`. Which root runs in production belongs to the deployment tickets.
12. **Independent-verifier dispositions of items 1–6 (recorded, not reopened).**
    - Item 1 (`cancelled(billing)`): acceptable; PROVIDERS §7.2 documentation follow-up still required.
    - Item 2 (FC5/FC8 placeholders): acceptable. They stay non-owning placeholders and must move to their owners atomically, with no duplicate public definition.
    - Item 3 (digest): no change in #97. The conformance suite proves P1 wire parity against a supplied Rendered request. It does **not** prove stored-record provenance or digest integrity.
    - Item 4 (429/503 deferral): acceptable for now. `SubmitResult` is a discriminated union, so a deferral outcome carrying same-Job backoff, `Retry-After` and admission-deadline semantics can be added additively.
    - Items 5–6 (synchronous submit, R22 propagation, probe subset): deferred to their T0 steps.
13. **No frozen-contract amendment.** The repairs change only `tools/arch-rules/` and touch no FC1, FC10 or FC11 surface.
