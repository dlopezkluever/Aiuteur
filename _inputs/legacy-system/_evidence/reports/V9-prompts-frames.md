## 3. Prompt-assembly pipeline (`POST generate-prompts`)

### 3.1 Inputs gathered by the route (`projects.ts:3573-3838`), in order
1. `projects` row: `id, active_branch_id, visual_style_capsule_id` filtered by `user_id` (L3582-3591).
2. `scenes` row in active branch (L3594-3603).
3. `shots.*` for scene ordered by `shot_order`, optionally `.in('id', shotIds)` (L3606-3620). 400 if none.
4. `scene_asset_instances` with `project_assets!inner(id,name,asset_type,description,image_key_url)` (L3623-3643) -> `SceneAssetInstanceData` (L3646-3662): `effective_description = effective_description || description_override || project_assets.description || ''`; `image_key_url` = instance image; `master_image_url = selected_master_reference_url || project_assets.image_key_url`.
5. `asset_angle_variants` (status completed) for character assets (L3665-3696).
6. `location_views` for location assets (L3699-3736).
7. Style capsule: `StyleCapsuleService.getCapsuleById(project.visual_style_capsule_id)` (L3739-3750). No code path in `src/` or `backend/src` writes `projects.visual_style_capsule_id` (grep: only reads at `projects.ts:3584,3740`, `frames.ts:527,569,2156,2216`, `contextManager.ts:499`); Stage 5 stores the style as `stage_states.content.locked_visual_style_capsule_id` (`Stage5Assets.tsx:227`). Result: unless the column is set outside the app, `styleCapsule = null` and style context = `'No visual style capsule applied.'` (`promptGenerationService.ts:762`). Status UNKNOWN at runtime; settle by querying `projects.visual_style_capsule_id` in a real DB.
8. `ContextManager.estimateContextSize` log only (L3753-3759).
9. Shot -> `ShotData` incl. `camera_distance/height/movement/direction_id`, `location_asset_id`, `start_continuity` (L3762-3785).
10. `transformation_events` confirmed for scene with trigger/completion shot embeds (L3788-3802).
11. `shotAssetAssignmentService.hasAssignments/getAssignmentsForScene` -> `Map<shotId, {scene_asset_instance_id, presence_type}[]>` (L3809-3829); failure -> legacy (all assets).

Not gathered: scene script text / scene heading, beat sheet, master script, previous shots' prompts, previous frames, writing style. "Previous shot" is used only as `previousShot` from the same request's array for the deterministic continuity heuristic (`promptGenerationService.ts:1085-1087`).

### 3.2 Per shot (`generateBulkPromptSets`, `promptGenerationService.ts:1048-1121`) - strictly sequential `for` loop
1. `resolveOverridesForShot` (transformationEventService) if events.
2. `aiStartContinuity = determineContinuityLink(shot, previousShot)` (L1014-1041): no previous -> `none`; continuity_flags matching `/cut|jump|transition|time.?skip|new.?scene|later/i` -> `none`; setting string differs -> `none`; `parseCameraField` shotType and angle equal -> `match`; else `camera_change`.
3. `generatePromptSet` (L883-966):
   - `scopeAssetsForShotContinuity` (L344-363): locations kept only if `project_asset.id === shot.location_asset_id` (none kept if shot has no location id); non-locations filtered by assignment set if assignments exist.
   - `enrichAssetsWithAngleMatch` (L370-439): character -> `matched_angle_url` (target angle from `mapCameraToAngleType`, fallback front); location -> `matchShotToLocationView` (assigned `camera_direction_id` else score height +2 / distance +1 / alias +3, else `is_primary`), delta description, `location_reference_strategy`.
   - Transformation overrides swap `image_key_url` (and clear `matched_angle_url`).
   - `buildAssetContext` (L673-756): CHARACTERS / LOCATIONS (+ camera direction, view description, ANGLE DELTA) / PROPS, each `- Name [inherited, carry_forward] [tags]: description <ref note> [TRANSFORMING...]`.
   - `buildStyleContext` (L761-786): `VISUAL STYLE:` design pillars, descriptor_strings, labels, `Avoid:` negatives.
   - Reference manifest: presence-aware `buildFrameReferenceManifests` (L612-663; throughout->both, enters->end, exits->start, passes_through->video-only; locations both) if assignments for this shot exist; else `buildNumberedImageManifest` (L469-603) single list. Sort: location 0, character 1, prop 2 (docstring L462 says "characters -> locations -> props": CONTRADICTED by code; test `promptGeneration.test.ts:206` asserts locations first). URL priority non-location: `matched_angle_url || image_key_url || master_image_url`; location: matched direction view (+establishing view), else asset image. Entries carry `label 'Image #N', assetName, url, type, role identity|style, referenceRole, reason, source`.
   - LLM call 1 `generateFramePrompt` (L1128-1190) then LLM call 2 `generateVideoPrompt` (L1200-1260; receives framePrompt arg but it is NOT interpolated into either prompt string).
   - Heuristics: `determineRequiresEndFrame` (L793-824): any `is_transforming` -> true; static CU w/o dialogue -> false; else camera contains dolly/track/pan/zoom/crane/steadicam OR dialogue OR duration > 8. `determineCompatibleModels` (L829-847): Veo3 always; 'Runway Gen-3' if frame prompt <= 500 chars and no dialogue; 'Kling' if duration <= 10.
4. Per-shot try/catch -> `{success:false,error}`.

### 3.5 Persistence (`projects.ts:3840-3891`)
For each success: `UPDATE shots SET frame_prompt, video_prompt, requires_end_frame, ai_recommends_end_frame, compatible_models, reference_image_order, end_frame_reference_image_order, ai_start_continuity, start_continuity = aiStartContinuity || 'none', prompts_generated_at, updated_at` (Promise.all, errors not checked). ### 3.6 What a regenerate overwrites vs. preserves
Overwritten for each regenerated shot (no merge, no "edited" guard): `frame_prompt`, `video_prompt` (user edits replaced; prior text survives only as a `text_field_versions` row if it was versioned or backfilled), `requires_end_frame` (user toggle lost), `compatible_models`, `reference_image_order` (user replacements via PUT reference-images and user-upload references lost), `end_frame_reference_image_order` (user end-ref overrides lost; set to null when no assignments), `ai_start_continuity`, `start_continuity` (user choice replaced by AI choice).
Single-shot regenerate (`shotIds=[uuid]`): `shots` array has length 1 so `previousShot = null` -> `aiStartContinuity='none'` -> `start_continuity` forced to `'none'` and no continuity context passed to the frame-prompt LLM (`promptGenerationService.ts:1085-1091`; `projects.ts:3856`). Same truncation affects subset regenerate of multiple non-contiguous shots (previous = previous in subset).
Preserved (not touched): `end_frame_prompt`, `continuity_frame_prompt` (NOT cleared even when new `start_continuity` is `none`, unlike PUT), `selected_continuity_base_frame_id`, `frames` rows/images, `frame_links`, `shot_asset_assignments`.
Text versions: cap `MAX_VERSIONS=8` per entity+field; at cap the oldest non-selected is deleted before insert (`textFieldVersionService.ts:181-202`). Version create is non-atomic (cap check, next number, deselect, insert, write-back are separate calls).

3. `generateFrames` (`frameGenerationService.ts:311-495`), sequential over shots ordered by `shot_order`:

   - `fetchShotReferenceImageContext` (L626-709): persisted `reference_image_order` -> `{url, role}` (role style only if entry `providerRole`/`role` = style, else identity); if `selected_continuity_base_frame_id` points to a generated/approved frame with image, prepend it (identity) unless already present; role `reuse_match` if same `camera_direction_id`, else `reuse_edit`.
   - `ensureFrame(shot,'start', previousEndFrameId)` (insert `pending` if missing).
   - Only if start status `pending|rejected`: branch (a) continuity base -> `buildReuseEditPrompt` (L542-554, appends "REUSE/EDIT CONTINUITY BASE: The first attached reference image is the selected base ...") ; (b) `start_continuity==='match' && previousEndFrameId` -> copy prev end `image_url/storage_path` to start, status `generated`, `continuity_base_role:'match_copy'`, no job row; if prev end has no image -> normal gen; (c) `camera_change && previousEndFrameId` -> reference link target (`frame_links link_type='reference'`) else previous end frame -> `generateWithCameraChangeAnalysis` (L720-840: vision `analyzeReferenceFrame` -> `continuityCompositionService.loadSceneAssetsForContinuity` -> LLM `generateContinuityFramePrompt` -> job with refs `[prevEnd(identity), ...shotRefs]` -> save `continuity_frame_prompt`); (d) normal `startFrameGeneration` with `shot.frame_prompt`.

## 8. Aspect ratio
`projects.aspect_ratio` ('16:9'|'9:16') -> `FRAME_DIMENSIONS` -> job `width/height` (1280x720 / 720x1280) persisted on `image_generation_jobs` and used for `estimateCost` and result metadata only. `NanoBananaClient.generateImage` does not pass width/height/aspect ratio to Gemini (no `generationConfig`; L118-130). Output aspect ratio is whatever the model returns; returned metadata echoes requested size. The only aspect cues reaching the model are reference images and prompt text. UI renders frames in `aspect-video` boxes (16:9) regardless of project ratio (`FramePanel.tsx:270, 341, 564, 571`).

## 9. Failures, timeouts, stuck jobs, concurrency
- Prompt LLM: 30 s race timeout per call; llm-client 3 retries; per-shot failure isolated in bulk; response 200 with `failed` count.
- Image job: in-process fire-and-forget promise; no queue, no worker, no sweeper (grep: no `setInterval`/cron/stuck handling in backend). Server restart mid-job leaves job in `queued|processing|generating|uploading` and frame in `generating` permanently. No user-facing cancel. Recovery paths that exit `generating`: upload variant, select-generation (if >=2 completed jobs exist), or calling `/status` (no UI).
- Racing jobs: two regenerations of the same frame create two jobs; each completion writes the frames row by `shot_id+frame_type`; last finisher wins regardless of `current_job_id`.
- Concurrency: `generate-frames` handler creates jobs sequentially (awaiting DB writes, and awaiting vision+LLM for camera_change shots) but image provider calls run concurrently in the Node process (one background promise per job, unbounded). Prompt generation is strictly sequential per shot (2 LLM calls per shot, frame then video).

## 11. Invalidation / staleness facts
- Editing `frame_prompt`/`video_prompt`/`end_frame_prompt` (any path) does not change `frames` status, does not mark frames stale, does not delete or flag videos. `frames.prompt_snapshot` retains the prompt used.
- `reference_image_order` is a URL snapshot taken at Stage 9 generation time. Later changes to scene asset images, angle variants, location views (Stage 8) are not reflected in frame generation until prompts are regenerated (frame gen reads only the persisted column; `fetchShotReferenceImageContext` L626-637).
- Presence-aware Stage 9 generation always writes a non-empty `end_frame_reference_image_order` when the shot has assignments with images; `resolveEndFrameReferenceImages` treats any non-empty value as a user override (L575-579), so the within_shot post-transformation image swap (L584-618) runs only for legacy shots without assignments. Stage 9 built the end manifest from the same transformation-overridden assets as start; for a within_shot trigger shot `ShotAssetOverride.image_key_url` is the pre-state image and `post_image_key_url` is separate (`transformationEventService.ts:43-51`), so the stored end refs carry the pre-state image. (Code-level inference; runtime UNKNOWN.)
- `match` frame_links propagate on regenerate/inpaint/upload/select-generation of the source, but propagation reads the source's current `image_url` at call time (old image for async jobs).
- Regenerate breaks incoming links of the regenerated target (plain regenerate, upload variant, select-generation); correction/edited-prompt regenerate and inpaint do not.
- Selecting a generation clears `approved_at` and sets status `generated`.
